# Задание 4. Передача актуальных ставок в кол-центры и план реализации

В рамках четвертого задания разработано архитектурное решение по передаче актуальных базовых ставок по депозитам в собственный кол-центр банка и внешний партнёрский кол-центр перед стартом масштабной маркетинговой кампании, а также сформирован план реализации (Roadmap) на 6 и 12 месяцев.

## Ключевые архитектурные выводы

1. **Единый источник правды без повторного создания баз данных**:
   - Базовые ставки публикуются сотрудниками банка один раз в рабочем месте «Контура заявок и ставок» (с версионированием и кэшированием).
   - Отдельный справочник ставок в АБС или в базах кол-центров не создается.

2. **Два разных способа интеграции под возможности участников**:
   - **Собственный кол-центр банка** (200 операторов, Java/Spring, внутренняя сеть) подключается онлайн через **REST API (HTTPS)** к сервису каталога ставок. В интерфейс оператора добавляется легкий виджет ставок.
   - **Партнёрский кол-центр** (100 операторов, внешняя закрытая система без API-интеграции с банком) получает актуальные базовые ставки в виде **файла-снимка (CSV/XML)** через защищенный файловый канал (SFTP).

3. **Безопасность и защита персональных данных**:
   - Партнёрский кол-центр разгружает только телефонную линию банка по общим консультациям.
   - Персональные данные, заявки клиентов с сайта и специальные ставки партнёру **не передаются**.

4. **Поэтапный план реализации (Roadmap)**:
   - **0–6 месяцев (MVP и запуск кампании):** запуск единого реестра ставок, REST API каталога, виджета в КЦ банка, файлового экспорта партнёру, онлайн-формы на сайте, модуля в интернет-банке и адаптера АБС для ручной обработки бэк-офисом.
   - **7–12 месяцев (Целевая архитектура):** внедрение автооткрытия депозитов без участия бэк-офиса, перевод интеграций на Apache Kafka и обеспечение активного резервирования сервисов (99.9% доступности).
