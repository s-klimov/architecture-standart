### **Нефункциональные требования**
Новые ограничения этого кейса плюс те NFR задания 3, без которых решение разъедется.

| **№** | **Требование** |
| :-: | :- |
| NFR1 | Один источник правды: базовые ставки для сайта, ИБ, КЦ банка и файла партнёра берутся из контура. Иначе после кампании операторы и сайт назовут разные цифры. |
| NFR2 | Партнёрский КЦ не вызывает API банка. Интеграция — **файл**. Транспорт — выкладка файла банком (SFTP или эквивалентный файловый канал, который партнёр уже умеет забирать). SFTP здесь не «API-вызов», а доставка файла. |

| NFR5 | Свежесть. После публикации ставки кэш и API КЦ обновляются за минуты. Файл партнёру — при каждой публикации и страховочно по расписанию (не реже раза в час в часы кампании). В имени/шапке файла — версия и время. |

| NFR7 | Если недоступен партнёр или файловый канал — КЦ банка и каналы заявки работают. Если недоступен контур — оператор банка не выдумывает ставку; файл партнёра остаётся последней валидной версией до TTL. |

| NFR9 | Канал выкладки: отдельная УЗ партнёра, только свой каталог, ключ/пароль, журнал кто забрал файл. Файл можно проверить по контрольной сумме. |
| NFR10 | Заявки с сайта по-прежнему разбирает **только КЦ банка**. Партнёр разгружает **голосовой** поток консультаций по условиям, не контур ПДн. |

### **Решение**

Принимаем решение: **не строить второй справочник и не открывать партнёру API. КЦ банка читает каталог контура по HTTPS. Партнёру банк выкладывает снимок той же опубликованной версии файлом.**

Так кампания не разъезжает цифры по Excel и почте, АБС не становится витриной, а внешняя система партнёра остаётся снаружи контура ПДн.

| Команда | Роль в этом изменении |

| Интернет-банк, команда банка (10) | API каталога и **экспортёр файла** в контуре (.NET, MS SQL). Ядро MVC 4.5 не трогают. |
| Интернет-банк, подрядчик (10) | **Не участвует** — то же ограничение S3, что в задании 3. |

| IT банка | Каталог выкладки файлов, УЗ и ключи партнёра, ретеншн. |
| Бэк-офис депозитов и кредитов | Публикуют ставки в рабочем месте. Без них файл и виджет пустые. |

##### Комментарий к контексту

В центре — контур ставок, уже принятый в задании 3. Слева люди, которые **говорят** цифры клиенту. Справа — партнёр: жёлтый пунктир, потому что это чужая система. Стрелки разные: фиолетовые — человек, синие — HTTPS внутри банка, зелёный пунктир — выкладка файла.

Сайт, интернет-банк и АБС на этой схеме не детализируем: они не меняют способ передачи ставок в кол-центры. Сайт и ИБ уже читают тот же каталог; АБС справочник не хранит.

##### Комментарий к компонентам

Режем только то, без чего кейс не объясняется.

**Контур заявок и ставок**

1. **Рабочее место ставок** — публикация версии справочника.
2. **Сервис каталога** — отдаёт базовые ставки кэшем (тот же API, что витрина сайта/ИБ).
3. **Кэш витрины** — чтобы звонок и сайт не били в тяжёлый расчёт.
4. **БД контура (MS SQL)** — мастер версий; не Oracle.
5. **Экспортёр файлов** — по событию публикации и по таймеру собирает файл и кладёт его в канал выкладки. Отдельный компонент, чтобы смена транспорта (SFTP → другой файловый канал) не трогала API каталога.
6. **Исходящий буфер / задание на выгрузку** — таблица MS SQL: «версия N ещё не выложена / выложена». Тот же приём, что outbox в задании 3.

**Система КЦ банка** (платформа подрядчика, без новой CRM):

1. **UI оператора** — виджет актуальных ставок рядом с карточкой звонка.
2. **Сервис-адаптер ставок (Java)** — ходит в API каталога, не в АБС и не в файл партнёра.

**Канал выкладки файлов** — инфраструктура банка: каталог, УЗ партнёра. Это не микросервис с доменной логикой.

**Система партнёра** — чёрный ящик. На входе файл, на экране — ставки для скрипта.

#### Логика выбора

1. **Не ломаем решение задания 3.** Ставки уже вынесены из Excel и из АБС. Повторять справочник в КЦ или у партнёра — вернуть as-is в новом месте.
2. **Два потребителя — два шва под их возможности.** КЦ банка умеет HTTPS и живёт в контуре банка — ему API. Партнёр умеет только файлы — ему снимок. Одинаковый *смысл* (базовая ставка версии N), разный *транспорт*.
3. **Партнёр разгружает телефон, не заявки.** Иначе снова откроем внешний контур ПДн, который в задании 3 сознательно закрыли.
4. **Банк публикует файл сам.** Партнёр не ходит «внутрь» за ставкой. Это закрывает и формулировку «нет API-вызовов», и контроль: мы решаем, *когда* и *какой* снимок ушёл.
5. **Экспортёр в контуре, не в АБС и не в ядре ИБ.** Команда банка на .NET, без релиза подрядчика ядра, без нагрузки на Oracle.

### **Альтернативы**

**А1. Отдать партнёру тот же HTTPS API каталога (VPN / белый список).**

Отклонено. У партнёра нет возможности вызывать API. Даже если «протянуть VPN», появится внешняя зависимость на доступность контура, контур ПДн и договор на онлайн-интеграцию — это не MVP кампании.

**А2. Кладти ставки в АБС и пусть оба КЦ читают оттуда.**

Отклонено. Повторяет отклонённую А2 задания 3: перегруз Oracle, партнёр в АБС всё равно не войдёт, Excel не умрёт. АБС — учёт вклада, не витрина.

**А3. Снова Excel по почте, как as-is.**

Отклонено. Это текущая проблема: расхождение цифр, нет версии, ставки в почте. Кампания только усилит хаос. Почта не проходит NFR3/NFR9.

**А4. КЦ банка тоже кормить файлом «для единообразия».**

Отклонено. Лишняя задержка на звонке «здесь и сейчас». Система КЦ уже в банке и на Spring — синхронный каталог дешевле и свежее, чем файл.

**А5. Отдать партнёру заявки с сайта вместе со ставками, чтобы они и консультировали, и qualифицировали лид.**

Отклонено. Внешний контур ПДн, нет юридического контура банка, спецставка и статус заявки останутся в двух местах. Партнёр в MVP — только голос по **публичным** условиям.

**А6. Партнёр ходит на SFTP «как за API» и тянет расчёт персональной ставки.**

Отклонено. Персональная ставка требует идентификатора клиента; это уже не файл-справочник. SFTP не замена расчётному API. Персональные цены — интернет-банк и контур, не партнёр.

#### **Недостатки, ограничения, риски**

- **Файл отстаёт от API.** Оператор банка и оператор партнёра в первые минуты после публикации могут назвать разные цифры. Снимаем: публикация → сразу выгрузка, в скрипте партнёра — называть версию/дату файла; при сомнении эскалация в КЦ банка.
- **Партнёр может загрузить битый или старый файл.** Нужны контрольная сумма, отказ от частичной загрузки, хранение предыдущей валидной версии.
- **Релиз виджета КЦ зависит от подрядчика.** Смягчение то же, что в задании 3: Java-экспертиза в команде АБС, объём — чтение каталога, не новая CRM.
- **Канал выкладки — новый операционный контур.** Потеря ключа, переполнение каталога, «файл лежит, но партнёр не забрал». Нужны алерт «версия N не забрана за T минут» и дежурство IT, не менеджер с флешкой.
- **Скрипты партнёра живут отдельно от системы.** Если бизнес обновит ставки, но не скрипт, оператор прочитает одну цифру в UI и другую в бумаге. Версия файла должна попадать в скрипт или в шапку экрана.
- **Кампания всё равно может перегрузить КЦ банка.** Партнёр снимает консультации по *базовым* условиям. Сложные случаи, спецставки и лиды с сайта остаются в банке — запас по людям всё равно нужен.
- **Этот ADR не автоматирует открытие вклада.** Горизонт года (без бэка, только фронт в отделении) по-прежнему из задания 3 и roadmap, не из файлового шва.
