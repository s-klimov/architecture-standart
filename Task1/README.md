# Задание 1. Карта IT-ландшафта и схема интеграции приложений (As-Is)

В рамках первого задания проведен анализ текущего состояния (As-Is) процесса открытия депозитов в банке «Стандарт».

## 1. Состав файлов задания

Диаграммы подготовлены в формате draw.io (открываются через [app.diagrams.net](https://app.diagrams.net/) или плагин в VS Code / Cursor):

| --- | --- |
| `it-landscape.drawio` | Карта IT-ландшафта: матрица подразделений банка (строки) и бизнес-возможностей 2-го уровня (колонки) |
| `application-integration.drawio` | Схема интеграции приложений: сквозной процесс открытия депозита As-Is по дорожкам участников |

## 2. Основные выводы по текущему процессу (As-Is)

1. **Ручной расчет ставок и зависимость от Excel/почты**:
   - Базовые ставки по депозитам рассчитываются сотрудниками отдела кредитования вручную в Excel (с учетом ставки ЦБ и кредитных рисков).
   - Готовый файл ежедневно рассылается по электронной почте в бэк-офис депозитов. Единой системы или сервиса ставок в банке нет.
   - Согласование специальных ставок для клиентов также происходит через переписку по email, что занимает от 20 минут до 1 часа.

2. **Отсутствие цифровых каналов для оформления депозита**:
   - **Сайт банка** (PHP + React) работает исключительно как информационная витрина и не умеет принимать заявки.
   - **Интернет-банк** (ASP.NET MVC 4.5) используется только для платежей и просмотра текущих счетов (напрямую читает БД АБС), но функционал открытия депозитов в нем отсутствует.
   - Единственный способ открыть депозит для клиента — физический визит в отделение.

3. **Бумажный документооборот и высокая нагрузка на сотрудников**:
   - В отделении сотрудник фронт-офиса распечатывает договор на бумаге, клиент подписывает его от руки, после чего скан документа вручную загружается в АБС.
   - Каждая операция требует ручного участия бэк-офиса депозитов.

4. **Изолированность партнерского кол-центра**:
   - Внешний партнерский кол-центр не имеет интеграции с АБС и банковскими системами, операторы работают только по статичным скриптам.

5. **Риск перегрузки АБС**:
   - АБС (Delphi + Oracle PL/SQL) является центральной монолитной системой учета. База данных Oracle уже испытывает повышенную нагрузку и масштабируется только вертикально. Любая попытка подключить онлайн-каналы напрямую к БД АБС приведет к деградации производительности всего банка.
